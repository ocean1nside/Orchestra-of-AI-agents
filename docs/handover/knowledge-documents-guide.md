# База знаний: как готовить документы

Индекс: [`README.md`](README.md) · Шаблон: [`knowledge-content-template.md`](knowledge-content-template.md)  
Studio: **База знаний** → **+ Добавить документ** · Проверка: **Просмотр чанков**

---

## Процесс (обязательный для файлов)

1. **Соберите смысл** — одна тема на файл (импорт, биллинг, сброс пароля…).
2. **Загрузка файла в Studio:** после выбора файла автоматически запускается **ИИ-подготовка** → вкладка **Текст** → проверка → **Загрузить и индексировать**.
3. **Уже загруженный документ:** кнопка **«Разобрать через ИИ»** (переписывает оригинал в Markdown и запускает reindex). Обычный Reindex **не** меняет текст — только перенарезает тот же сырой docx.
4. Статус **«В поиске»** → **Просмотр чанков** → проверка фрагментов.
5. Проверьте бота вопросом по документу.

Без индексации документ в базе есть, но **поиск (RAG) его не видит**.

---

## Форматы файлов

| Формат | Когда использовать |
|--------|-------------------|
| **`.md`** | Основной формат после ручной или ИИ-подготовки |
| **`.txt`** | Простой текст UTF-8 с абзацами |
| **`.docx`** | Исходник; желательно прогнать через ИИ-подготовку |
| **PDF** | Не поддерживается → конвертация в `.md` / `.docx` |

Кодировка `.md` / `.txt`: **UTF-8**.

## Как устроена индексация (2025)

1. Оригинал → `storage/knowledge/originals/`.
2. Извлечение текста (md/txt/docx).
3. **Умная нарезка на чанки:**
   - сначала границы: абзацы (`\n\n`), заголовки Markdown, строки, предложения, слова;
   - лимит **~1000 символов** на чанк;
   - перекрытие **~150 символов** между соседними чанками (стыки не теряются в поиске).
4. Текст чанков → **Postgres** (`kb_chunks`), векторы → **Qdrant**.
5. В ответ бота попадает до **8** релевантных чанков.

Слова **не режутся посередине**, если в тексте есть нормальные абзацы и заголовки.

## Что должно быть в содержании

Документ для поддержки — это **инструкции и факты**, не презентация.

**Обязательно по возможности:**

- Заголовок `#` и разделы `##` по подтемам.
- **Конкретные пути UI:** «Настройки → Пользователи → Импорт».
- **Пошаговые действия** (нумерованный список).
- **Ошибки и коды** (отдельный подраздел на код).
- **Форматы данных** (CSV, поля, кодировка).
- Абзацы **300–900 символов** — один смысл на абзац.

**Избегайте:**

- Простыней без пустых строк и заголовков.
- Выдуманных шагов (ИИ-подготовка не должна их добавлять — проверяйте глазами).
- Десяти копий одной инструкции в разных файлах.
- Сканов без текста, cp1251 в `.txt`.

Готовый шаблон: [`knowledge-content-template.md`](knowledge-content-template.md).

## Подготовка через ИИ (Studio)

Кнопка **«Подготовить через ИИ → Markdown»** в модалке добавления:

1. Читает ваш файл (.md / .txt / .docx).
2. Переписывает по правилам из `normalize_rules.md` (структура, абзацы, без выдумок).
3. Открывает вкладку **Текст** для проверки и правки.
4. Вы сохраняете уже подготовленный Markdown.

**Требуется** `OPENAI_API_KEY` в `apps/orchestrator-api/.env` (модель: `KNOWLEDGE_NORMALIZE_MODEL`, по умолчанию `gpt-4o-mini`).

ИИ **не заменяет** экспертизу: сверьте факты, коды и названия кнопок с оригиналом.

## Эмбеддинги и поиск

| Режим | Поведение |
|-------|-----------|
| `EMBED_PROVIDER=hash` (dev) | Слабая семантика, чаще лексический fallback |
| `EMBED_PROVIDER=openai` (prod) | Нормальный векторный поиск; после смены — **полный reindex** |

---

## Контроль качества

1. **Просмотр чанков** — нет ли обрывов на полуслове, не слишком ли мелкие/огромные фрагменты.
2. Вопрос боту формулировкой **как в документе**.
3. После смены нарезки или ИИ-подготовки старых файлов — **Reindex** документа или всей базы.

---

## Если документ не находится

1. Статус **«В поиске»** (`indexed`)?
2. Есть чанки в превью?
3. Reindex документа / всей базы.
4. Вопрос ближе к формулировкам в тексте.
5. В проде — `EMBED_PROVIDER=openai` и ключ.
