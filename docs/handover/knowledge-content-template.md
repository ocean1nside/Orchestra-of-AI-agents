# Шаблон содержимого документа для базы знаний

Скопируйте и заполните. Такой текст хорошо режется на чанки и хорошо ищется ботом.

```markdown
# [Название темы — как в списке Studio]

Кратко: о чём этот документ и для какого сценария (1–3 предложения).

## Когда использовать

- Ситуация 1
- Ситуация 2

## Предусловия

- Что должно быть настроено до начала
- Нужные права / роли

## Пошаговая инструкция

1. Откройте [Меню → Подраздел → Действие].
2. Укажите …
3. Дождитесь статуса «…».

## Форматы и ограничения

- Формат файла: …
- Кодировка: UTF-8
- Обязательные поля: …

## Частые ошибки

### Код E100 — …

Причина: …  
Что сделать: …

### Сообщение «…»

Причина: …  
Что сделать: …

## Связанные разделы

- Если нужно X — см. документ «…» (только если такой документ есть в базе).
```

## Правила содержания

| Делайте | Не делайте |
|---------|------------|
| Один раздел = одна задача пользователя | Смешивать 5 несвязанных тем в одном файле |
| Точные названия кнопок и путей меню | «Перейдите в настройки» без уточнения |
| Коды ошибок и обязательные поля | Общие фразы без фактов |
| Абзацы 3–8 предложений под `##` | Простыня на 50 страниц без заголовков |
| Тот же язык, что у пользователей | Маркетинговый вода без инструкций |

## Подготовка через ИИ в Studio

Если исходник «грязный» (Word, старый PDF→docx, копипаст):

1. Загрузите файл в модалке **+ Добавить документ**.
2. Нажмите **Подготовить через ИИ → Markdown** (нужен `OPENAI_API_KEY` в orchestrator-api).
3. Проверьте текст на вкладке **Текст**, поправьте при необходимости.
4. **Загрузить и индексировать** → **Просмотр чанков** для контроля качества.

Правила для ИИ: `apps/orchestrator-api/src/orchestrator_api/modules/knowledge/normalize_rules.md`.
